# Witch

Witch is a new videogame by Ed Saperia (Ed, 2026-10-03). Its design so far is `DESIGN.md`. Engine (Ed, 2026-10-03): prototype in Three.js in the browser, port to Godot once Ed is happy; so the game's state and rules live in `src/rules/` with no Three.js in them, and `src/render/` draws them. Anything else not yet decided: ask Ed rather than assume, and record his answers here.

Work on Witch follows the shared rules in [edsaperia/dev-ops](https://github.com/edsaperia/dev-ops): `AGENTS.md`, `CONVENTIONS.md` and `claude/QUESTIONS-PAGE.md`. This file adds what is specific to Witch and wins where the two disagree.

## Deploys

The playable game is a static site on GitHub Pages, served from the `gh-pages` branch by `.github/workflows/pages.yml`:

- a push or merge to `main` builds the game and publishes it at the site's root, https://edsaperia.github.io/witch/ — **merging to `main` deploys**;
- each pull request from this repository is built and published under `/pr-<number>/` (https://edsaperia.github.io/witch/pr-<number>/), and the workflow comments that link on the PR; closing the PR removes it;
- documents-only changes still rebuild and republish the same game (no `docs` lane yet).

Pages must be switched on once in the repository's settings (Source: *Deploy from a branch*, `gh-pages`, `/ (root)`); until then the links return 404. A deploy is verified by opening the link and checking the seed and the game load.

## What's new

The start screen shows a **What's new** panel: the last three entries of the changelog, newest first. The changelog is **one small file per change** in `config/changelog/` (Ed, 2026-10-05: so builders working in parallel don't conflict), collected at build time by `src/changelog.ts`:

- Every push that changes something Ed can see **adds a new fragment file**, `config/changelog/<yyyy-mm-dd>-<slug>.json` (e.g. `2026-10-05-bigger-areas.json`), holding `{ "version": null, "items": ["…"] }`: its bullets in plain player-facing words ("Trees no longer pop in and out"), not commit-speak. Several pushes of one piece of work may add to that same fragment.
- Once its build has a number (the playable-link comment), **write that number into your own fragment's `version`** on your next push. Never edit anyone else's fragment.
- `config/changelog/archive.json` holds everything up to round 9 and is frozen: never edit it. There is no shared list to edit.
- Fragments with the same version make one entry (the newest file's items first); the current build's (`version: null`) shows as the build being played. `src/changelog.test.ts` checks every file's shape.

## Testing

CI (`.github/workflows/ci.yml`) runs on every push and pull request, in this order:

- `npm ci`
- `npm test` (Vitest: the rules modules in `src/rules/`, including the partition checked against the Art Lab's own `makePartition`, and the geometry of the on-screen cues in `src/render/indicator.test.ts`)
- `npm run typecheck` (`tsc --noEmit` over `src/`, `config/` and `vite.config.ts`)
- `npm run build` (Vite, into `dist/`)
- then, in a second job, `npm run smoke:quick` on that build: the quick smoke test (`tools/smoke/quick.cjs`, headless Chromium with Playwright installed in CI and its Chromium cached; a few minutes). It loads the game at 1280×720 with `?quick=1` (only the art the start needs), starts, flies about 5 s on the ground, rises, flies about 5 s in the treetops and descends, and fails on any page or console error, a blank picture, or a witch that doesn't move, rise or descend. Its screenshot and log are kept as the run's `smoke-quick` artifact. Then the music check, `node tools/music-lab/check.cjs`: it builds the Music Lab and, in headless Chromium, renders every section of `config/music-style.json` offline (plus a build into a wave under siege and the game's mix far off and damaged), failing on a script error, a fetch, silence, NaN or clipping, then plays it live and jumps to a wave. Run it before every push that touches the music. The full smoke test below still covers pops, floating, big windows, touch and waves.

**Push first, slow checks after** (Ed, 2026-10-04: "All the builders should push first and run checks afterwards"): when a change works, run the fast checks (`npm test`, `npm run typecheck`, `npm run build`, and `node art/check.mjs` if it touches art), then push straight away so the bot builds a playable version, and post a short REPORT with the version. Then run the slow checks (the smoke run, preview sheets); report any failure, fix it and push again. Post the FINAL once the slow checks are done. Never hold a playable build back waiting for the smoke run.

Not in CI, run by builders before a FINAL: `npm run build && npm run smoke`, a headless Chromium smoke test (`tools/smoke/smoke.cjs`, Playwright from the machine's global install; never `playwright install`) that flies both modes on the laptop and phone layouts, drives the touch controls, flies a path through every zoom step in both modes failing on any pop (anything appearing or vanishing in clear view), flies full-speed straight lines in both modes at Ed's window sizes (1900×1240 at DPR 1, 2000×1076 at DPR 2) failing on any pop or any sprite instance set but not drawn (`view.stats.dropped`), flies a 10 s full boost north over the treetops frame by frame at a fixed 1/60 s (`window.witch.frame`) failing if its frames' own work (rules and view, `view.ms` by part) passes 22 ms at p99 or 40 ms at worst, runs four party waves, and saves screenshots to `previews/` (`RECORD=1` also saves `previews/flight.webm`).

## Glossary

Literal, stable names for the parts of the game, as Ed and the builders agree them. The game's own terms are in `DESIGN.md`'s glossary; these are the prototype's.

- **Area type**: one of the kinds of area: Ed's 30, defined with their art in `art/areas.js` (his columns: floor, wall objects, small objects, big objects, set piece, creature). `config/area-types.json` adds the game's own numbers per type (how thick its big objects stand).
- **Wall objects, small objects, big objects, set piece**: Ed's columns. Big objects stand like trees (trees split into top and bottom halves; mounds, boulders and logs whole); small objects scatter like undergrowth; wall objects stand where areas meet and block nothing; a set piece shows in a quarter of its type's areas, in the clearing.
- **Party witches**: the witches who fly in to the dancefloor, one for each active soundsystem (`PARTY_OUTFITS`, `partyWitch(seed)` in `art/witch.js`): our witch's model in a party look (hat, hair, top, shades, glow sticks) and palette; they and our witch share the party poses (dances, pairs, social, running, resting).
- **Pair poses**: party poses two witches do together (`WITCH_PAIRS`): each draws her own sprite, placed so their `pair` anchors meet (the partner mirrored, so they face each other; the conga's hands on the `back` of the witch ahead; the twirl's partner spins under the raised hand; the broom limbo is two witches holding a broom level and a third leaning back under it).
- **Witch genome / witch generator**: a witch as genome data (`art/witchGenome.js`): her hat (shape, crown height, brim, lean, band), hair, top, cloak (none, short, long, hooded), broom (classic, fan, twig or round bristles; handle length and bend; bristle length), accessories (headphones, sunglasses, glow sticks, a scarf, a satchel, a glowing pendant, earrings) and palette (per part, as `DEFAULT_OUTFIT`). `genomeLook(g)` gives the look and outfit `witchSprite` draws; `WITCH_GENOME` is ours and draws her exactly; `witchGenome(seed)` is a new witch within the limits in `WITCH_AXES` (always a pointed hat with its glowing band, and a broom).
- **Lean cycle**: the witch's ordinary flying speed at ground level as a 4-frame loop (`pose: "lean"`), played faster with speed.
- **Treehouse**: the witch's home near the dancefloor (`art/treehouse.js`), a tall timber tower of storeys stacked up a giant living tree, mostly wood with modern touches, its shingled witch's-hat tower standing above the treetops; she starts the game sitting behind the decks in its cutaway DJ booth (`sit` pose at its `seat` anchor, the `fore` sprite, the DJ table, drawn over her), the camera zoomed in on its `camera` anchor; its tree is a giant, unlike any forest species. She stays seated (`witch.seated` in the rules) until the first move or rise. It stands just beyond the dancefloor's clearing (`map.treehouse`, placed by `treehouse` in the tuning file).
- **Layout**: an area type's `layout` in `art/areas.js`: how its trees and undergrowth are arranged (pattern, density, clumping, glades, height mix, lean, terrain, decorations, a one-line feel); data the prototype's layout engine reads.
- **Modern relics**: the forest's reclaimed modern world (`art/relics.js`): cars, trolleys, cones, broken highway, odds and ends, an overgrown playground and sports grounds, with suggested arrangements; no brands or text.
- **World decorations**: scattered features any area can have, independent of its own props (`art/decor.js`): ruins, rocks, freak trees, and the lake kit; an area's `layout.decor` will weight their families.
- **Party relics**: giant, legend-sized bottles half-buried in the forest floor, 3 or 4 to a map (#87; `art/partyRelics.js`, `PARTY_RELICS`; Ed: "colourful transparent bottles of different shapes"): a tall wine bottle, a round flask, a square decanter, a tapering hexagonal bottle, a tall spiral-fluted bottle and a teardrop potion, each in its own coloured glass, see-through, the liquid inside glowing in its own colour (so it reads as magical, not scenery), motes rising from the neck, and a light (`light`) that lights the ground round it. The witch digs one up and it becomes a sigil (`relic`, one for them all: the flask's silhouette in gold) she places by a sleeping legend to wake it happy. Each has a `glint` point where `partyRelicGlint` (a four-point star in 4 frames, bigger at the treetop zoom) plays now and then, so it can be spotted from above. Not the **modern relics** (`art/relics.js`).
- **Country pieces**: the farm and street decorations and the small scenes' own pieces (`art/country.js`): tractor, bales, fences, gate, signs, lampposts, a bus shelter and the like; single pieces, overgrown, no text.
- **Scene**: a few related pieces arranged together that count as one piece on the map (`art/scenes.js`), listed as reused piece sprites with positions in metres and a footprint, never baked as one sprite; it faces one of two ways (as authored or mirrored). Groups of fences and of hay bales are scenes. Large scenes (cemetery, car park, scrap yard, places of worship, castle and classical ruins) are built from **landmark pieces** (`art/landmarks.js`); a building you can fly into is two pieces, its far and near halves.
- **Party objects**: the small pieces scattered many times over a partified area (`art/party.js`) so it reads as party ground, even in the dark: litter, balloons (shiny, never glowing, recoloured by palette, bobbing), light sources (neon or warm), campfires (animated, with point lights), furniture and set dressing, and the home stretch's decorations (class `home`: stepping stones, a mushroom ring, lantern posts, path lights, a speaker stack, crates, flower pots, a signpost, a branch arch), by size class; neon ones bake in any party neon. **Party clusters** group 3 to 8 of them in the scenes' format.
- **Attack effects**: the art a fight draws (`art/effects.js`, `effectSprite(id, { frame, variant, zoom })`): projectiles, beams (start, a repeating loop, end), pulses (the quake ring, the screech, upheaval and slam rings, a spore cloud), webs, the mole's mound, charge dust, stun stars, strong ("!!") and resisted ("tink") hits, trait marks, telegraphs (a target circle, a line, a wind-up flash, the quake's reach), hit sparks and the slow and knockback marks; in greys with a tint mask (the wild red, the party a creature's neon), light (for the dark) and dark (for bright ground), at a ground and a treetop zoom. `ATTACK_EFFECTS` says which each attack uses.
- **Path kinds**: the ten kinds of path (`art/paths.js`), each a ground-space strip the prototype sweeps along a spline, with end and junction patches and 3D edge props; the railway adds points, a broken end, a crossing and landmarks.
- **Hero dancefloor**: the round floor of 30-across glass tiles in a carved stone rim (`art/dancefloor.js`), lit by the prototype's tile-lighting engine: a pattern library (shapes, loops, fills, the switch-on sequence and one shape per area from its creature's sigil), each with its beats, palette of neons and party level (1 calm to 4 full rave), transitions (wipe, iris, dissolve, burst), and the tile looks (unlit, lit at three intensities, grout, rim).
- **Dancefloor speakers**: the ring of 12 single-column speakers round the dancefloor, replacing its stones (`dancefloorSpeakerSprite` in `art/soundsystem.js`), the far half facing the centre and the near half facing out, so every one shows its front; drawn at three angles and mirrored; playing, damaged and destroyed.
- **Tufts**: tiny ground-cover sprites (8 to 13 px) the prototype scatters thickly over an area's floor (`art/tufts.js`, `tuftSprites`/`bakeTufts`): grass, long grass, fern, heather, rushes, moss, clover, needles, litter, pebbles, and rarer flowers and mushrooms, each with its share of the area's tufts.
- **Sway mask**: a map the size of a sprite (`art/sway.js`), its grey (R, B) 0 where it stays still in the wind (trunks, rock) up to 255 at the leafy tips, its G the **pixel-wind code** (`swayCode`: a region's phase and stiffness); trees (whole, top and bottom), leafy props and tufts carry one, exported as `.sway.png`.
- **Pixel wind**: the game's sway (`src/render/sprites.ts`, by the code in the sway mask's G): each region of a sprite (a crown's blob from the genome generator, else a cell of about 10 by 8 px) moves whole, a whole art pixel at a time (at most 2), out of step with the others by its own phase, as far as its stiffness lets it; `?wind=smooth` brings back the old per-pixel slide. `windShift` (`art/sway.js`) is the same rule on the CPU, for previews and the check.
- **Tall pieces**: the sparse, tall things in the open areas without trees (`art/tall.js`): snags in the log pile, cairns and standing stones on the moor, pillars and a tall cairn at the stone shrine, rock spires and a stalagmite in the ravine; `big` entries flagged `sparse` (their share of the area's big objects).
- **Tree species**: the kinds of tree in `art/trees.js` (`TREE_SPECIES`): the original six and fifteen UK species (oak, beech, ash, lime, sycamore, horse chestnut, rowan, alder, Scots pine, yew, hawthorn, holly, hazel, weeping birch, larch); each area names a main species and often a minor one.
- **Area flora**: each wooded area type's trees (`AREA_FLORA` in `art/flora/areas.js`): 3 to 6 species with their shares, its main kind first, and its palette (leaf saturation and brightness, times the species' own; the hue is the area's `leaf`); `areaTreeVariants` deals the species into the area's ten tree variants by share (`floraSlots`), each with the area's own tree character. The fantasy species grow only as a minority where magic suits (glowcap in the hazel rings, vinewood in the garden and the holly thicket, the crystal-leaf tree at the cave mouth).
- **Plant genome**: a tree or bush species as data (`PLANT_GENOMES`, `BUSH_GENOMES` in `art/flora/genomes.js`): its form, the generator that grows it and its params, the style rules it bends, its life below the crown, its colours and its height-class growth. `TREE_SPECIES` and `bush` are grown from them. The **genome generator** (`art/flora/blob.js`, generator `"blob"`) grows a tree from levels of branches (Weber–Penn style) under a crown of 3 to 9 lit **blobs** filled with **leaf stamps** (t3ssel8r style); it draws the ten newer species, three of them fantasy (glowcap, crystal-leaf tree, vinewood). `?flora=new|fantasy|all|<ids>` grows those species in every wooded area (carried to the art worker in the style); the lab's Flora panel shows them.
- **Sleeping legend**: an area's legend of its species as it lies asleep for centuries (`art/legends.js`, `legendForm(id, st, { frame, facing })`): half sunk in its area's earth, head down, eyes shut, its glow gone to stone and old wood, mossed and grown over so it passes for a boulder, log or mound, in 2 slow breathing frames at the legend's scale, `origin` the ground under its middle. No waking sequence or awake redraw yet (Ed, 2026-10-04: "just the sleeping form"). Batch 1: bat, marten, elk, stoat, owl, snail; batch 2: wolf, fox, badger, boar, stag, hare, bear; batch 3: lynx, otter, beaver, ram, squirrel, dormouse, salamander; batch 4: toad, raven, mole, hedgehog, woodlouse; batch 5: snake, moth, glow-worm, spider, stag beetle (`LEGEND_POSES`): all 30.
- **Genome**: a species as data (`art/genome/species.js`, #79): its template, builder, palette, proportions (`body`, `head`), parts (`parts`: ears, tail, feet, horns, antlers, tusks) and markings (`coat`); `speciesOf` makes the builders' species object from it, `genomeHash` its bake-cache key. Edit the record, not the builder, to change a species.
- **Template**: a body plan (`art/genome/templates.js`): quadruped, avian, flyer, serpent, insectoid, squat; its builders, its sockets and the part tags each allows, tags that exclude each other, its gait (for the live rig) and, for the quadruped, its **size curves** (four numbers, baby to legend, for each proportion that changes with level).
- **Material mask / palette row**: a creature sprite baked once as which material each pixel is (and whether it's an outline), coloured at draw time from a palette row (`art/genome/palette.js`: `bakeMask`, `paletteRow`, `paintPixels`, `PALETTE_GLSL`); a **palette variant** is a curated coat (`PALETTE_VARIANTS`: frost, ember, shadow, gold, moss, rose, ash) that recolours a species with no rebake.
- **Silhouette check**: each species' shape (young and adult, facing us) shrunk to 24 px and compared with every other's by overlap (`art/genome/silhouette.js`); two closer than 0.15 fail `art/check.mjs`. It caught the dormouse reading as a squirrel (it has its own long, low tail now).
- **Live rig**: `?rig=1` (#79 stages 4–5; without it the game is unchanged): wild four-legged creatures and snakes put together each frame from **rig parts** (`art/genome/parts.js` `rigParts`: torso, head and tail pieces baked at five headings, the other three mirrored, with their pivots, and discs to string legs and serpent bodies), baked by the art workers into one atlas page per species and level (`rig` jobs, keyed by the genome's hash, the least used let go past 48), and laid out by `src/render/rig/rig.ts`: legs as two-bone IK chains stepping on a trot's phases with a duty factor by speed, a serpent as a follow-the-leader chain weaving behind its head, the body leaning into acceleration, crouching before a charge or a leap, stretching in a charge, tucking its legs in the air, its tail swinging out on turns. `node tools/rig/strip.mjs wolf,snake` draws frame strips of a scripted run; `node tools/rig/demo.cjs` (ARENA=...) screenshots the game with it; `node tools/rig/perf.cjs` times 300 creatures with it off and on.
- **Remoteness**: how far an area is from home, 0 at the dancefloor's area to 1 at the map's edge; creatures grow more numerous and older with it.
- **Tilt-shift**: the post-process blur toward the top and bottom of the screen that makes the forest look like a miniature.
- **Tuning file**: `config/tuning.json`, the numbers Ed edits (speeds, camera, density, glow, pixel size, creatures, bloom, tilt-shift).
- **Style file**: `config/style.json`, a style saved in the Witch Art Lab; every sprite is drawn from it.
- **Top half / bottom half**: a tree's crown and its trunk, drawn as two sprites; tops show in treetop mode only. The bottom half also carries the life below the crown (ivy, moss, epicormic sprigs, low boughs, a skirt on yew, holly and the conifers), so ground mode isn't a forest of bare poles.
- **Debug overlay**: the panel toggled by `~` or a three-finger tap: frame rate, seed, area type, mode.
- **Partified**: an area the party has reached: a soundsystem in its clearing, string lights round it, motes. Home is partified from the start.
- **Wave**: one step of the party spreading: every area bordering a partified one is partified at once, every `party.interval` seconds (N brings the next one, P pauses the timer).
- **String lights**: lines of party bulbs hung between pairs of trees round a partified area's clearing.
- **Smooth effects / pixel effects**: `?fx=smooth` (default) draws mist, far haze and canopy dapple as soft gradients; `?fx=pixel` draws them as dithered pixel steps.
- **Pop**: an object appearing or vanishing in clear view between frames. `?debug=cull` tints anything that has just appeared red and frames anything that has just vanished in red for a second; the smoke check fails on any pop.
- **Talk / invite**: on the ground she talks by herself (no button: Ed, v244) to the nearest invitable creature within `invite.talkRange`, sticking with it within `invite.cancelDistance`: emoji bubbles take turns, and after its talk time (babies 3 s, young 6 s, adults 12 s) it is invited, and so leashed (and healed to full). Wild legends can't be invited (a legend let go on a knockout can, at `invite.talkTime`'s fourth value).
- **Sigil stack**: the sigils of the creatures leashed to the witch, floating above her head, newest at the bottom. The Sigil button (E; gamepad X; touch "sigil") puts the bottom one down as a rune on the ground (a **leash point**) or picks a placed one back up.
- **Party animal**: an invited creature, in party gear, dancing on the beat (`beat.bpm`).
- **Partified border**: the sparkling line round the outside of the partified region, in each area's sigil colour.
- **Sim step**: the rules advance only in fixed `STEP`s (1/60 s, `rules/game.ts`), driven only by inputs and the seed; `stepGame` runs as many as a frame makes up, and the view draws eased between the last two (`interpolated`). Rules code never reads the wall clock or `Math.random`.
- **Witches**: `game.witches[]`, one per player (body, leash, spell, dash, health, knockout); `game.witch`, `game.leash` and `game.spells` are the first's.
- **Combat**: `rules/combat.ts`, its attacks as data in `config/combat.json` (levels' health and power budget; melee, shot or quake; windup, cooldown, modifier). Party (leashed) against wild; same kind never fights same kind; wild young and up attack the witch on the ground.
- **Siege**: a woken area's wild creatures marching on its new soundsystem (`combat.sounds`, health `combat.soundsystemHealth`; home is "home", the dancefloor). A fallen one is **ruined** (its party over, no wave wakes it again); its besiegers march on to the next-nearest. The run is **over** (`game.over`) when none stands.
- **Enraged**: a wild creature a wave has set on a soundsystem (`siege`, `enraged`): angry red eyes (the art's `woken` look), and it can't be invited.
- **Knockout**: the witch at no hits left: her stack lets go bottom first, one every `knockout.releaseEach` seconds, each creature turning **neutral** (`wanderTo`) and walking to its kind's nearest area; then the teleport home.
- **Action bar**: the eight slots 1 2 3 4 Q W E R along the bottom (bindings in `platform/input.ts`: `KEYS`, `PAD`, `ACTION_BAR`).
- **Path network**: the paths, roads, railways and streams (`src/rules/paths.ts`, on the map as `map.paths`): seeded spline lines with tree-free corridors and bushes thick along their edges, drawn as ground ribbons with the art's strips (`src/render/paths.ts`). A path's kind follows the area it crosses; broken railway lets trees grow between the sleepers.
- **Decor**: ruins, rocks and freak trees (`art/decor.js`) scattered sparsely as scenery (`Forest.decorNear`), never on a path, in an area's central clearing or by the dancefloor.
- **Rolling ground**: the hills everything stands on (`src/render/height.ts`): one height h(x, z) from noise, levelled across paths and into plateaus under the dancefloor, treehouse, soundsystems, set pieces, grounds and ponds; kept in a half-float texture round the witch that the shaders read and `groundHeight` reads the same way. Drawing only: the rules stay flat (`ground.hills`, `?hills=`). Never steeper than the camera's shallowest pitch can see over (Ed, v289): the hills are made broad enough (`SLOPE_SCALE`).
- **Ley lines**: the glowing line to the next objective (`src/rules/leylines.ts` the order, `src/render/leylines.ts` the drawing): from the last runestone reached (by its wave, or its quest: `onAreaDone(party, cell, time)`) to the next in wave order (`leyLines.links` 1; more for a short chain, each fainter), wandering along the valleys, a shimmer flowing toward the next stone, on the ground in both modes; reaching the next stone drains the old line into it and draws the next out. `?ley=0` hides them.
- **Ride**: the smoothed height she and the camera fly over the rolling ground (`src/render/ride.ts`): the ground averaged along her flight behind and ahead, eased, never letting her feet into the ground (`witch.heightSmooth`, `heightLookAhead`, `heightClearance`). Drawing only.
- **Bend**: the world curving away toward the top of the screen in treetop mode, every vertex ahead of the camera's focus dropped by curve × d² (`camera.curve`, `?curve=`), so the night sky shows over the forest.
- **Music style**: `config/music-style.json`, the music as data, like the art's style file: tempo (it sets `beat.bpm`), swing, key and scales, chord progressions, synth patches, parts with their patterns, sections and the arc; every sound synthesised (`src/platform/audio/musicEngine.ts`), every tune generated from the run's seed (`src/rules/musicScore.ts`).
- **Section**: a stretch of the track (intro, forest, deep, breakdown, build, drop, dark, industrial, breaks, ether, chip, phonk, whisper, knockout…): which parts play which patterns, its chords and its low-pass. Sections change only on 4-bar lines (`blockBars`), so every change lands on a phrase.
- **Arc**: the music's steps through a run, one per wave (the last repeats): each wave's arrival sections, the ones it loops, and the build that leads into the next wave and ends as it lands (`src/rules/musicPlan.ts`, the conductor). The home speakers' boot plays the intro. Hooks: while she's knocked out (`ko`) the knockout section plays; a standing soundsystem with wild creatures fighting at it adds the siege parts, by how near it is (`siegeNear`).
- **Beat clock**: `g.beat` (`src/rules/beat.ts`), beats by game time: each wave's tempo is its arc step's `bpm` (Ed: 120 rising to about 140 by the finale, as `beat.tempos` in the tuning), eased in over `tempoRampBars` from the block line the wave's music lands on, the beat continuous through every change. **Beat-time** (`beatTime(g.beat, time)`) is game time as it would run at the base tempo: anything that reckons beats as time × `beat.bpm` / 60 (lasers, the dancefloor, dancing, pulses) is given beat-time instead of time, and so follows the tempo.
- **Music mood** (Ed, 2026-10-04): the two best references for the overall mood are Grimes' "4ÆM" and Grimes and Janelle Monáe's "Venus Fly" (dreamy, ethereal layers crashing into hard, distorted, industrial drums and breakbeat energy); only their genres are used, never their sounds or tunes. `node tools/music-lab/analyse.cjs` measures every section (loudness, bands, each part soloed, spectrograms) for tuning the mix.
- **Sound effects**: the game's synthesised sounds besides the music (`platform/audio/sfx.ts`): 💌s (a hit chime, the affection tick, the invite flourish by level), states (a growl turning enraged, a pop turning happy), legends (whale song: see Babble).
- **Babble**: speech without words, a voiced source through a vowel's formants (`platform/audio/babble.ts`): each 💌 is a syllable of the witch's (Ed, 2026-10-05: "rapid fire sounds like talking: you are inviting"), each burst a phrase lifting at the end; every animal attack is a burst in its own voice (`voiceOf`, `platform/audio/voices.ts`: higher the smaller and younger, each species its own; its **call** blended in, `config/creature-voices.json`: a family's call style (bird, canid, big, small, bug, snake, amphibian, bat, whistler, cat) and the species' tweaks, so you can tell what's talking; a new creature picks a family) by mood (`speechMood`: happy bright and rising, enraged clipped and falling with grit, wild grumbling); legends sing whale song instead (Ed, 2026-10-05: "deep and slow"; `platform/audio/whale.ts`): long gliding moans in a big reverb, happy rising, enraged groaning down, a sleeper moaning softly now and then, restless wavering, a long-range attack's wind-up one building swell (`sfx.whale`). At most `sfx.voice.animals.maxVoices` at once, the farthest giving way. `platform/audio/sfxCues.ts` plays them from the rules' events and what changed each frame. A woken area that has joined the party is heard as the music style's `party` parts (`partyNear`, rules/musicPlan.ts).
- **Music Lab**: `tools/music-lab/`, one page that plays the engine through the game's own mix: a pretend run (boot, waves, jump to a wave), any section on a loop, distance and damage, the hooks, knobs for the style, and the style's JSON to copy out. `?music=<section>` and `?music=wave<N>` preview the same in the game.
- **Fighting value (F)**: a side's strength by Lanchester's square law, Σ √(hp × dps) (`rules/power.ts`): young 15.5, adult 29, legend 76, babies 0.
- **Population growth**: every area starts with `population.start` (a baby and two adults) and, while wild, gains `population.growth.perWave` creatures a wave at levels by `growth.weights` (`rules/growth.ts`): kept as counts (`game.growth.pending`) until a witch comes within the creature simulation radius or the area wakes, then made out of her sight. The debug overlay's `wild` line counts them.
- **Strength**: a species' number (Ed, 2026-10-05: "just a number that goes up and down"), its multiplier on health and damage (`combat.json` `strength.species`, 1 when not listed; `strengthOf` in `rules/combat.ts`), never a legend's; its areas hold 1 / that many (`countScale` in `rules/growth.ts`).
- **Berry cost**: berries to evolve a level (`toEvolve(level, tuning, species)` in `rules/berries.ts`): the strength the level gains (`berries.cost.by`: "power", hp × dps, or "value", its square root) over `berries.cost.per`, rounded, at least 1: by "value" (Ed, 2026-10-05) 2 and 2 for a species of normal strength, so a berry buys the same fighting value for every species.
- **Pacing variants**: the balance simulator's ways of keeping pressure on without a cliff (Ed, 2026-10-04): **attrition** (only a share of a won siege's survivors march on) and the **director** (reinforcements for the areas the next wave wakes, by a budget growing with the wave and, by α, with the player's power). Simulator only so far.
- **Power meter**: the debug overlay's two lines: the party's F (leashed + parked, by level, berries and invites) and the enemy's (every marcher, and each siege with its count and its soundsystem's health).
- **Playtest log**: `src/platform/playtestLog.ts`: a sample every 10 s of play on this browser (localStorage `witch.playtest`, the last 8 runs); L or `?playtest=download` saves it as JSON.
- **Balance simulator**: `rules/balance.ts` and `tools/balance/sim.mjs` (see Testing).
- **Sky**: the night sky over the bend (`src/render/sky.ts`): gradient, stars, the moon, and clouds lit from below by the party (`sky`); left sharp by the tilt-shift.
- **Area legend / sleeping legend**: the one legend of its kind in every area, asleep (sunk and mossed over, scenery) until its area's wave wakes it, angry, to guard its area; beaten, it sleeps for good (DESIGN.md, "Sleeping legends").
- **Happy legend**: an area legend at peace, its buff on (by its quest: rules/quest.ts; or the debug key O). Home's is happy from the start.
- **Debug arena**: `?arena=wolf*4@2,beetle*3`, hers against the wild below the dancefloor; J sets it up again.
- **Dream / quest**: a sleeping legend's thought bubble, the sigil (in its level's variant) of the creature it wants; put that sigil down in its area before its wave and it's happy (rules/quest.ts).
- **Friendly area / guards**: an area whose legend's quest is done: its creatures leave her be while it's wild, and guard it as party animals once it's partified. An area whose quest isn't done wakes **angry**.
- **Posse / travelling**: a party animal near the witch on the ground (about 60 m, `config/travel.json`) or at its sigil is her posse and fights; anywhere else it travels: quiet both ways, along area borders, its leash drawn as its route.
