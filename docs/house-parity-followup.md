## Harness change, no game-rendering change

Both house shot tools use tools/house/shot-session.cjs. They install the existing benchmark holdSimulation interceptor before navigation; wait for ready, explicit start if paused, and art-idle; then assert the existing zero-step startingBoundary. They keep their original full-draw frame counts, dt and controls. Each draw is completed with gl.finish before the next is submitted, with separate real-clock draw/finish diagnostics and context-loss checks. Art is waited between steps. No threshold increase, dropped draw or scene whitelist is used.

Before capture,80zero-dt draws advance a held performance clock from10000100 through10008000, matching the existing benchmark fade-settling approach. Game clocks do not advance during settling. Loading mist is explicitly off (`loadmist=0`, as the benchmark already uses) in both builds, regular mist remains rendered at the fixed game clock. DOM animations are cancelled. A second held capture must exactly equal the first or the tool fails its parity precondition. Saved scene state includes game/her clocks, acc, position/mode, camera/projection matrices, light shader clocks, art pending, house visibility, WebGL loss and draw calls. A screenshot timeout after the `capture outside` log now occurs after all requested GL work completed; an earlier stall is localized by frame/finish logs.
