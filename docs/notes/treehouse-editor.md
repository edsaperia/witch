# Treehouse layout editor

Ed, 2026-10-31: "I just need the top down view and the camera view and the ability to move objects around and export the layout. Skip floorplan editing for now."

Open `treehouse-editor.html` beside the game (including under a PR preview). This standalone authoring page does not load gameplay or read/write player saves. The published house data is never changed. Choose a room/object, drag in the top-down plan, or type exact X/Z coordinates and a rotation. Shift-drag snaps to 0.5 m. Right-drag pans; the wheel and +/- zoom; Fit house and Focus selected change framing. Undo/Redo cover whole drag gestures and imports. Reset object/all restore the published baseline.

Both views use one layout. The plan's blue dot is the object's use position (the decks' seat), transformed rigidly with it. Rotation is clockwise in the plan, degrees relative to the published facing. A station's furniture model and its built-in parts turn as one; the editor does not simulate fitting/equipping, live hats or player clothes. The camera view uses the production floor painter, precomputed fixed wall quads, room decoration, furniture model generator and lighting at the house plane's 24° pitch. It is a layout preview, not the entire game's Ent/witch/atmosphere/postprocessing. Decks and the clothes pile currently have labelled grey proxy shapes. Room decorations stay fixed; they are not gameplay objects/stations. No room/floorplan editing.

Copy settings writes complete version-1 JSON and always fills the textarea. If clipboard permission is refused, the text is selected for ordinary copying. Paste a prior export and Apply pasted settings to reapply it; validation rejects missing/duplicate/unknown IDs, incompatible floorplans, non-finite/out-of-range values and inconsistent supplied use anchors. A failed import leaves the current layout intact. The export includes all objects, stable IDs, plan coordinates, relative angles and derived use positions. `terrace:decks` groups the decks and their seat. Its floorplan fingerprint includes fixed shape and baseline identity/size/anchors, so an export from incompatible source cannot silently move the wrong layout. `houseLayout.ts` is the pure reference for reapplication; an adopted export still needs an explicit coordinator change to the shipped data/consumer. No automatic adoption.

Fixed geometry remains generated by `virtual:house-standing`; authoring never rebuilds or edits it when furniture moves. No changes to PR1523 kitchen data or shared house renderer are needed. A later prototype merge should pick up its new objects through the shared assembled configuration.

## Coordinator visual QA

Builders do not run the browser without an allocated slot. Build the exact source with `WITCH_SHA` set to its full SHA, using `npm run build`; serve that build on the already allocated runner, then:

```
EXPECT_SHA=<40-character source SHA> node tools/house/editor-check.cjs https://<served-build>/treehouse-editor.html previews/treehouse-editor
```

The check first reads served `version.json`, checks real floor/camera pixels, drags a station, rotates it, exercises clipboard fallback, roundtrip import, invalid-import atomicity and undo/redo, and records screenshots/results. It starts no server. It must be run by the coordinator on an allocated runner; a syntax check is not browser acceptance. Human review should check the overview and focused station picture for clipping, layering and readable furniture. Publish requested screenshots only through `tools/shots/push.mjs`.
