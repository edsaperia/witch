# Deploys

<!-- summary: GitHub Pages and publishing: the gh-pages snapshot and its publisher, PR previews, garbage collection, version.json and the newer-build notice, and when a release counts as live. -->

Moved from CLAUDE.md as it stood (Ed, 2026-11-12: "Let's look at claude.md and see if there's a way we can compact/refactor it"); every rule and quote kept. CLAUDE.md keeps the short version: merging to `main` deploys, only the coordinator does that, and every pull request gets a preview at `/pr-<number>/`. Add to this file, not CLAUDE.md, when you change the deploys.

The playable game is a static site on GitHub Pages. CI (`.github/workflows/ci.yml`) writes each build into the `gh-pages` branch, and `.github/workflows/pages-publish.yml` publishes that branch's latest complete snapshot (Pages Source: GitHub Actions):

- a push or merge to `main` builds the game and publishes it at the site's root, https://edsaperia.github.io/witch/ — **merging to `main` deploys**;
- each pull request from this repository is built and published under `/pr-<number>/` (https://edsaperia.github.io/witch/pr-<number>/), and the workflow comments that link on the PR; closing the PR removes it;
- a documents-only pull request (every file under `docs/` or a `.md`) gets no preview, since it plays exactly prototype's game; main's deploy also drops previews of pull requests idle for a week (they come back on the next push). The snapshot must stay under Pages' 1 GB: it was ~1 GB on 2026-11-09.
- every build writes `version.json` beside the game (its label, `vite.config.ts` `versionFile`; main's at the root, a PR's in its `pr-<number>/`); a page left open reads it on load, on pausing and every five minutes, never from a cache, and while a newer build is up says so in the bedroom and on the pause page: "A newer version (v3712) is out", with a reload button (Ed, 2026-10-14; `src/app/newBuild.ts`), and so does a menu whose code a deploy has replaced under it (Hotel's #906).
- main's deploy deletes the root's stale build files before copying the new build (`tools/ci/pages-gc.cjs`): in the folders the build writes (`assets/`, `news/`, `online/`, `audio-test/assets/`…), whatever is neither in the new build nor referenced by the previous one's pages goes, so a page left open on the previous build still loads; `pr-*/`, `making-of/`, `version.json` and `.nojekyll` are never touched, and it deletes nothing if it can't find the previous build. Before it, every release's hashed files piled up (989 MB of the 1 GB on 2026-11-10).
- many deploys at once are fine: each writes only its own folder (main the root, a PR its `pr-<number>/`), and one whose push to `gh-pages` is beaten fetches the newer branch and tries again (up to ten times).
- publishing is serialised (one publisher at a time; GitHub keeps only the newest waiting request, and every publication takes the newest `gh-pages`, so a preview that displaces a waiting live request still publishes the new live root). The publisher makes its own Pages deployment call (not `actions/deploy-pages`): each attempt gets its own deployment name, a stuck earlier deployment that blocks it is cancelled, it waits up to 30 minutes and tries twice, a re-run of the workflow can deploy again, and the job fails unless the public `version.json` shows the root it published. If the site still shows an old version: Actions → Publish Pages snapshot → Run workflow.

A release counts as live only when https://edsaperia.github.io/witch/version.json (fetched with a cache-busting query) shows its build, not when CI's deploy job finishes. A deploy is then verified by opening the link and checking the seed and the game load.

Updates, 2026-11-12 (the CLAUDE.md compaction): the snapshot measured 406 MiB through the GitHub API (13,114 files: `pr-*/` previews 312 MiB, `making-of/` 58 MiB, the root's `assets/` 15 MiB), so the "~1 GB on 2026-11-09" above is history from before the garbage collection. "Hotel's #906" is the builder Hotel's pull request #906, which first gave the pause page its reload message when a deploy replaced its code.
