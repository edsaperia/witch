# The run

Native pause-key isolation (#1522, 2026-10-31): rejected Enter/NumpadEnter/Space keydown and keyup events aimed outside the pause UI cancel the browser default as well as propagation, so they cannot activate an underlying focused button. Opening pause focuses its visible button container with tabindex=-1 after mounting: immediate Enter/Space is cancelled, the first native Tab reaches Controls, and activation on a focused button still works. The container opens no corner panel, so the existing pad Back resumes immediately; Back in an explicitly opened corner panel closes that panel as before. Tab/Shift+Tab and arrows retain native defaults; resume does not restore old underlying focus. Native controls inside pause, Settings and the potion lab retain their existing defaults/routing. This preserves #1523's potion-lab Escape and single-step exceptions. Focused tests cover cancellation, native navigation, inside controls and focus; the coordinator owns real-browser acceptance.

Pause input stack (#1495, Ed's approved architecture review, 2026-10-30):
`platform/inputStack.ts` owns the page's registered overlay order. Pause is the
first migrated panel; chart, Studio, zoo, DJ booth, creator, telescope and Settings
remain separate later migrations, with no view/main split here. `Freeze` registers
pause on opening and removes it on resume, routes both key phases through the top
owner, and hides gamepad reads from lower owners. Native pause controls retain
browser defaults without propagating keys below pause; Settings keeps its legacy
window handler until its migration. The existing Studio first-Esc rule, Settings
Esc rule, pause/single-step recorder hooks and comment text-entry guard remain.
Pause/resume releases cached game input; keys held across the ownership transition
cannot repeat into the exposed panel until released. Browser focus loss clears
physical-key quarantine. Gamepad opening snapshots remain authoritative even if
pause closes and reopens with the same DOM between menu frames; a fresh Back is
recognised without requiring an intervening frame, while opening-held buttons
remain suppressed. Focused tests reproduce the formerly lost second Back and
compare exact recorded/replayed rules state across held-key pause/resume and
single-step. Browser/default-control and pause-on-top checks belong to the
coordinator's release check; unit tests do not prove a browser flake eliminated.

**Direct play after loading** (#1493, 2026-10-30): resumed nights, creator=0 links and bot games use the existing start action once ready, with no visible start card. A bot's asynchronous module must finish before its night starts. Bedroom wake-up and chart arrival retain their own gates; the old creator still waits for its spell-scroll action. Automatic starts keep the existing sound-only first-gesture prompt; that key/tap is not needed to begin play. Controls/Options can still borrow their hidden nodes, but main no longer imports the start-screen formatter, eager changelog or upcoming data. Nearby route/save/input tests do not establish audio, visual loading or browser interaction success. What's new returns in the following lazy Settings milestone.

Menu recovery (#1456, coordinator decision 2026-10-29): Settings refuses to clear the last Choose or Back input on each device (keyboard/mouse together, or pad), with a short row note. Swapping an input into an empty slot cannot indirectly steal either action's last input: the whole swap is checked before saving, and a refused swap changes nothing. Valid swaps and surplus-input removal still work; no extra pause gesture was added.

Gamepad menus (#1456, 2026-10-29): ordinary menus, including pause and its Controls / What's new / Options panels, follow the configured Choose and Back bindings. Settings alone retains the fixed ✕ choose / ○ back recovery layout. Start always pauses regardless of its remap. The chart and telescope readouts follow the last device and the current remaps. The legacy character creator remains outside this work: normal bedroom, sail and bed routes bypass it; URL switches and fallback/dev routes retain it. The zoo retains its in-world exits, with no parent-side ○ close.

Pause page's first frame (2026-10-30, the pause-on-top B flake): the pause page's pad menu is primed with the buttons held as the pause began (`platform/freeze.ts` takeOpenPad), not those held by its first frame, so a Back pressed after Esc but before a slow first frame (seconds on a software GL) resumes instead of being taken for the opening press.

Screen selection in Settings is offered only when the browser implements `getScreenDetails`; checking support does not request permission.

## Multiplayer rules groundwork (2026-10-29, PR #1457)

`stepGame` accepts an array of controls, exactly one per witch in stable ID order. The legacy scalar controls object remains supported for the host, with neutral guest inputs. Movement, fixed-step edge queues, spells, invitations, leash interactions, health, knockouts, wake-up and dressing are stepped for each witch; shared creatures and world phases advance once. `pausePage` in the recorded controls (or `setWitchPaused`) marks each player's actual pause page. Only every player pausing stops multiplayer; the legacy page's global clock flag cannot pause it for a station or DJ panel. Each actor clock runs at full speed while the shared world clock runs at normal speed unless every witch is landed in the treehouse (including at the decks). Legend circles still slow solo, and never slow multiplayer (Ed's answer, 2026-10-29). The existing bed hold ends the shared night only after every witch has completed it; completed holds leave witches asleep and immobile until that shared night ends, with no new wake gesture. Placed animal sigils can be picked up by any witch, with a single creature attachment retained. Wild watches retain every occupied area for three separated witches, and the zoo's outward-push hold belongs to each actor independently.

`nightSnapshot` retains each witch's real pause state and actor state, but excludes her transient input queue. Restore clears every queue and pauses all players until explicit resume inputs. `sharedNightProgress` exposes identical successful permanent unlocks to each valid player: chart discoveries after the existing finale settles; a collected find eligible for the existing bed/sail settlement after a win. This is a rules integration seam; writing other players' browser collections is **not implemented**. Temporary find loan handling is unchanged. No difficulty scaling or revive was added.

This is headless groundwork, not playable online co-op: no networking, phone, guest bedrooms, multiple views or server. The camera, view/audio lookup helpers, finale leader and existing page remain host-facing. Shared house inventory/equipment selection and per-player persistence need integration with the later multiplayer page; this PR does not replace those app/UI systems. The seeded replay test runs two witches for three minutes, comparing complete canonical night snapshots at checkpoints (including random cursors, combat, clocks, inventories and shared state), and a production-rules syntax check bans `Math.random` access. A temporary pre/post solo trace matched SHA-256 snapshots at 10, 20 and 30 seconds; no solo behavior change is intended.

Saving a night (Ed's go, 2026-10-29): `app/nightSave.ts` checkpoints the rules and the page's look, loan and chart-recording flags every five seconds in IndexedDB (`witch.nights`, keyed by the game's URL path, so PR previews stay separate). Hiding or leaving the page requests a final best-effort checkpoint; browsers can terminate before that transaction completes, so the periodic checkpoint is the fallback. A load offers Resume night / Start a new night before making the game. Only the same build and the explicitly linked seed/island/world can resume; a plain game link can resume the saved island. Resume skips arrival, dressing and link-driven rules resets; player-settings baselines are saved too, so voice scaling and disabled shake/flash don't compound. A night stays resumable through its afterparty until she sleeps or sails, when its save is cleared. No checkpoint is made during a dream or while the next island is loading. Storage failures are shown without interrupting play. `rules/nightSnapshot.ts` rebuilds static map/forest functions and restores dynamic rules state, graph references and every seeded random cursor; tests compare subsequent simulation steps. Bots, debug/reproduction links and automation leave the save alone; `?resume=0` disables it, `?resume=1` explicitly enables it for testing. Full night saves are versioned and are not migrated across builds yet.

A fresh bedroom night becomes saveable only once the wake-up has her out of bed (`wake.open`), including after sleep or a sail; the alarm, snooze and stretch cannot create a resume offer. The old opening still waits for its start card to close. `app/opening.test.ts` and `app/nightSave.test.ts` cover these gates, including a real wake-up advanced through the rules.

Gamepad foundation (#1456, 2026-10-29): every game action in the bindings table is dispatched on the pad, including Talk held/toggled, Auto-talk and the playtest actions. Tests remap actions across all 17 standard buttons. `platform/rumble.ts` observes hits, knockdowns, landing, waves and the night's outcome; it emits one modest pulse per event, capped at 160 ms and strength 0.35, and silently ignores unsupported/disconnected devices. The Accessibility page's Gamepad rumble setting defaults on for older saves; off, Reduce flashing or a paused game suppresses it. The rules and save lifecycle are unchanged.

Input reliability (2026-10-29, #1454): `platform/input.ts` reads every action's press before consuming keyboard/mouse edges, including Talk and Auto-talk. All three mouse buttons have held state; their down/up events track chords and releases over panels, while touch compatibility mouse events are ignored. `game.ts` queues hat presses with the other one-shot actions until the next fixed step and consumes each once, whether a rendered frame runs zero, one or several steps. Regression tests cover 30/60/144 fps, mouse holds for inviting/using (stump, bed and sigils), toggle bindings, chords, blur and start-screen consumption. Stump casting and the floor-hat rules are unchanged.
