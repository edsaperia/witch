# Save slots

Ed, 2026-10-30: "We should have save slots that hold progress and settings. By default open the previous one, but you should be able to select a different slot or a new slot from a tab in the settings screen, which restarts the night."

**Save slot storage** (`src/app/saveSlots.ts`): a version-1 index at `witch.saves.v1` holds the last-used slot and independent slot metadata. Existing progress and settings keys listed in `SLOT_KEYS` become `witch.save.<slot-id>.<old-key>`. The wrapper passes device diagnostics and unrelated keys through unchanged. Each data item remains independent, so malformed settings in one slot do not prevent reading the others. Existing readers remain responsible for validating each item's contents. An unreadable index is kept for recovery and blocks persisting a replacement selection; existing namespaced bytes are never replaced with older legacy bytes during recovery.

**Single-save migration**: copy the legacy values as exact strings into slot `s1`; keep their original keys. Publish the index only when every legacy read and copy succeeds. A failed copy stays in memory for the page, logs once per key, and does not publish a migration marker, even if a new slot is created afterwards. A later page can retry from the originals. Slot 1 keeps the existing IndexedDB night key (the URL path), so no large night is copied or discarded. Other slots use `<path>#save=<id>`. Runtime progress/settings readers use the page's adapter, pinned to its boot slot even after a new last-used slot is chosen.

**Slot switching**: Settings → Saves lists slots with island, recorded nights and date. The old single save has no historical night count, so it says earlier nights were not counted. `NightAutosave.flush` waits for any active checkpoint and then saves the latest paused state; `switchSave` selects only after that completes. Refuse a reload while storage writes exist only in memory. Choosing another/new save reloads the plain game path into that slot, clearing old URL overrides and arrival frames. Slot control bindings are loaded afresh too. Metadata updates merge the latest persisted index to preserve other open tabs' slots and last-used choice; new slot IDs are opaque random IDs. The page's Current label and data adapter remain pinned to its boot slot. Existing logs, device quality history and builder tooling remain shared. No rename/delete in this pass.

**Compatible nights**: resume automatically on plain game loads; accept matching SavedNight/NightSnapshot format versions across build numbers, retaining explicit seed/island/world link identity. If the format or restored graph is invalid, keep its existing slot data, start a fresh night for this page and disable overwriting that night. Other slots remain selectable. Comment restore retains its separate staging key and recording/build checks. No browser validation is claimed without a coordinator slot.

**Save format guards** (`src/app/saveFormat.test.ts`): normalized TypeScript declarations for SavedNight, the graph codec types and Game have fingerprints keyed by their format versions. A declaration edit fails the guard until its version is deliberately bumped and a new baseline reviewed (or a compatible migration is added). Comments and formatting do not affect it. This checks the envelope, graph representation and top-level Game declaration; it does not claim exhaustive coverage of every nested imported game type. Runtime roundtrip and compatibility tests remain necessary.

**Compatible mushroom extension (PR #1523)**: the version-1 envelope and graph remain unchanged. `restoreGame` creates deterministic mushroom state only when an older snapshot has no `mushrooms` field; snapshots that contain it retain their baskets, carried mushrooms, brew and active trips exactly. The format guard retains the original version-1 Game fingerprint and records the reviewed additive migration separately. It also verifies that removing only `mushrooms` recovers that original fingerprint, so unrelated Game changes cannot hide in this migration. The migration regression covers both old and current snapshots.

Checks: `npm exec -- vitest run src/app/saveSlots.test.ts src/app/saveFormat.test.ts --maxWorkers=1`, `npm run typecheck`. Full suite, browser and combined release checks belong to the coordinator.
