# Config files

Part of Witch's notes (CLAUDE.md is the index): the tuning file and its schema, the style file. Moved here from CLAUDE.md as it stood (housekeeping, Ed 2026-10-23: a note an area, so pull requests add to their own area's file, not one shared file); every rule kept. Add to this file, not CLAUDE.md, when you change this area.

- **Tuning file**: `config/tuning.json`, the numbers Ed edits (speeds, camera, density, glow, pixel size, creatures, bloom, tilt-shift). Its schema is `config/schema/tuning.schema.json` (every knob's type and range; `src/rules/schema.ts` checks it, `src/rules/tuningSchema.test.ts` fails on an unknown, missing, mistyped or out-of-range knob) and its reference, generated from the schema and the file's `_` notes, is `config/KNOBS.md`. After adding or renaming a knob, or editing a `_` note: `node tools/config/schema.mjs --add --docs` (string choices and name-keyed records go in `TUNING_OVER`, `src/rules/tuningSchema.ts`). Changing a value needs nothing (the reference lists no values). The other configs are checked the same way (`src/rules/configSchemas.ts` lists them, the one list: each config's file, its records keyed by name and its string choices; no copy of it here, after the copy that stood here fell two behind, 2026-10-28; `src/rules/configs.test.ts` checks each against `config/schema/<name>.schema.json` and that the species, attacks, area types and buff kinds they name are real). After adding a field to one: `node tools/config/schema.mjs --add` (or `--init` to re-infer every schema).
- **Style file**: `config/style.json`, a style saved in the Witch Art Lab; every sprite is drawn from it.
