# Hosting on Render: decision note

Checked2026-10-31; comparison only. No Render, domain, Pages-source or deployment changes. Ed decides when multiplayer goes live.

**Availability/cost.** Render supports free CDN-backed static sites and separate Git PR preview URLs, updated on pushes and deleted when PRs close. Free static-site previews have no instance charge; bandwidth/build minutes still count. Single-service previews are available on Hobby; full-stack preview environments require Pro+. Current published plans: Hobby $0/month,5GB bandwidth,500build minutes,25services; Pro $25/month,25GB,1000minutes. Public egress overage is $0.15/GB, shared with relay traffic. Confirm Ed's actual/legacy plan and whether preview instances count toward its service limit in Billing; neither account state nor an unlimited-preview entitlement was verified. Sources: [static sites](https://render.com/docs/static-sites), [previews](https://render.com/docs/service-previews), [pricing](https://render.com/pricing), [pipeline limits](https://render.com/docs/build-pipeline), [bandwidth](https://render.com/docs/outbound-bandwidth).

**Caching.** Render allows path-based custom headers. Use revalidation/no-store for HTML and `version.json`, long immutable caching only for hashed assets, and verify actual compressed transfer/cache headers. The game's no-store version poll must see the correct build label; cached mutable entry files must not hide releases. [Header configuration](https://render.com/docs/static-site-headers).

**Migration impact.** Vite's relative base helps relocation, but update hard-coded GitHub Pages PR-comment URLs, CI deployment/verification, docs and the canonical `pubcombo` helper. That helper was not found in this repo/dev-ops snapshot; its exact external location/owner needs checking. Preserve numeric monotonic `WITCH_VERSION`, source SHA and `version.json`: Render commit hashes alone do not satisfy our newer-build comparison. Preserve `?seed`/world/layout query strings and map old `/witch/` and `/pr-N/` links or keep old hosting available. Native Render previews use separate hosts, not our existing PR paths.

Changing origin hides localStorage and IndexedDB saves/settings/art caches. A redirect cannot transfer them. Keep the old origin available and build/test an explicit old-site export→new-site import migration, or tell players clearly that they start fresh. No save migration is implemented here.

**Relay/same-origin.** A static-site hostname and a relay hostname remain different origins even on Render. True same-origin needs the frontend and WebSocket endpoint behind one host (for example serving frontend files from the relay web service, or a separately verified upgrade-capable proxy). That simplifies URL/origin/session policy; it does not remove authentication/Origin validation. Don't assume static-site rewrites proxy WebSockets. [Render WebSockets](https://render.com/docs/websocket).
